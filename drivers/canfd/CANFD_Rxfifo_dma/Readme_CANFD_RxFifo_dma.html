Description

This test transfers the 64 MBs of CANFD0 set up as transmit Message buffers. This is configured on CORE0. On core 2, CANFD1 is setup with Rx FIFO to receive the 64 MBs by setting up 64 filter IDs. The reception through FIFO is done through DMA. CAN controller doesn't have an integrated DMA, so the MDMA is interfaced to CANFD RXFIFO and hardware support for trigger generated on FIFO fill triggers the MDMA read. This mechanism enables the FIFO read without core intervention Only MDMA stream 2 and 6 can be used to read the CANFD FIFO. This example is supported only on EV-SOMCRR-EZKIT.

The example does following:

  1. Core0 configures CANFD0 to send MB0 to MB63 in blocking mode.
  2. Core1 configures CANFD1 to receive 64 messages.
  3. All 64 messages, with ID 0 to 63 are received through FIFO.
  4. To enable this FIFO reception is enabled in CANFD1 and 64 FIFO filters are configured to allow 64 different IDs to be received through FIFO.
  5. Read of the the messages received in FIFO is done by MDMA.
  6. Messages received through FIFO are received in non-blocking mode.
  7. Once all messages are received, data received is verified.

CAN operation is configured for normal operation (non-FD) at 1Mbps with 80% sampling point.
CAN module clock is programmed for 100 MHz. Prescaling divider PREDIV = 4 which results in clock of 100/(4+1) = 20 MHz so Tq = 1000/20 ns = 50 ns

Sampling point = (SYNC_SEG + PROPSEG + PSEG1 + 2 )/(SYCN_SEG + PROPSEG + PSEG1 + 2 + PSEG2 + 1)
SYNC_SEG = 1 (fixed)
PROPSEG = 9
PSEG1 = 4
PSEG2 = 3

Overview

This example demonstrates the transmission of standard CAN messages using blocking API and the reception of the messages is done through FIFO in DMA mode of operation. Since CANFD does not have an integrated DMA controller, MDMA is coupled with CANFD to read the FIFO data. 'adi_canfd_RecvFifo_NonBlockingDma' API takes care of setting up the DMA and reading the data from FIFO
Since data received by DMA is not corrected for endianness, application code needs to correct the endianness of the data received for each message

"Successfully Received data from all MBs" and "All Done" printed to the console signifies the received messages are received correctly.

"Test failed" printed to the console signifies that the test example has failed. Other errors are also printed if any of the driver operation fails in between and the code is terminated.

User Configuration Macros

STANDARDFRAME : This macro define whether the message buffers are transmitted with standard ID or extended ID. This macro should be defined for standard frame and commented for extended frames. Macro should be defined/undefined on both core0 and core1.
ADI_CANFD1_CFG_MDMASTREAMID : This macro is defined in 'adi_canfd_config_sc59x.h' file for core1. This value can be set to either 2 or 6 to used MDMA2 or MDMA6 to read the FIFO data.

Hardware Setup

  1. Connect the DB9 cable between J7 and J8 on EV-SOMCRR-EZKIT
  2. Run core 0 to enable Core1 and Core2 and configure CANFD0 for TX
  3. Run core 1 to configure CANFD1 for RX
  4. Core1 will compare the received data with the reference data and declare the test status

Pinmuxing

The following pins are used for the CANFD operation:

  1. CANFD0_RX
  2. CANFD0_TX
  3. CANFD1_RX
  4. CANFD1_TX

External connections

Connect the DB9 cable between J7 and J8 on EV-SOMCRR-EZKIT
