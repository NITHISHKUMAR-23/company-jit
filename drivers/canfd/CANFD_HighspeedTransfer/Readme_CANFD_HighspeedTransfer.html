Description

This example demonstrates the CAN transfer in Flexi-date rate transmission with bit rate switching enabled to transfer the payload at 8 Mbps. This tests transfers all the MBs of CANFD0 configured on core0(decided by configuration of ADI_CANFD0_CFG_BLOCK0_MBSIZE/ADI_CANFD1_CFG_BLOCK0_MBSIZE' and 'ADI_CANFD0_CFG_BLOCK1_MBSIZE/ADI_CANFD1_CFG_BLOCK1_MBSIZE mcros in config file) set up as transmit Message buffers. On core 2, all MBs of CANFD1 are configured as receive message buffers to receive the corresponding message buffers from CANFD0. All the buffers are configured for FD mode with Bit rate switching enabled. Since the transfer are done in Flexi-data rate, the payload size can vary from 0-64 bytes This example only demonstrates the Bit rate switching and configuring the payload upto 64 bytes. This example is supported only on EV-SOMCRR-EZKIT.

The test demonstrates two things:

  1. CANFD operating in FD mode at max speed. Speed during data phase is 8.0 Mbps.
  2. The need for Delay compensation when operating at high speeds in Fast mode. This is to ensure the correct self-sampling at high speed This is enabled by setting the macro ADI_CANFD0_CFG_TRANS_DELAYCOMP_EN to 1 as CANFD0 is the transmitter. And programming the offset through ADI_CANFD0_CFG_TRANS_DELAYOFFSET to 4.
In this example one can experiment with the values of ADI_CANFD0_CFG_TRANS_DELAYOFFSET and see the working range from 0x2 to 0x9 without any error in CANFD transmission. Below and above this Delay offset there are some Bit0 errors in transmission. This test is written to transmit upto 14 64-byte FD MBs multiple times and receive them on CANFD1. Each set of MBs is verified everytime to ensure the correctness of the reception.

The example does following:

  1. Core0 configures CANFD0 to send all MBs with bit-rate switching enabled in blocking mode.
  2. Core1 configures CANFD1 to receive all the messages with data phase bit rate rate of 8 Mbps.
  3. Based on DLC macro, the payload length of each CANFD message is determined
  4. Once all messages are received, data received in all MBs is verified.

CAN operation is configured for normal operation (non-FD) at 1Mbps with 80% sampling point.
CAN module clock is programmed for 80 MHz

Prescaling divider PREDIV = 0 which results in clock of 80/(0+1) = 80 MHz
Tq = 1000/80 ns = 12.5 ns

Sampling point = (SYNC_SEG + PROPSEG + PSEG1 + 2 )/(SYCN_SEG + PROPSEG + PSEG1 + 2 + PSEG2 + 1)

SYNC_SEG = 1 (fixed)
PROPSEG = 45
PSEG1 = 16
PSEG2 = 15

For FD rate, BRS rate of 8.0 mbps is used by configuring following settings:

Prescaling divider PREDIV = 0 which results in clock of 80/(0+1) = 80 MHz
Tq = 1000/80 ns = 12.5 ns

Sampling point = (SYNC_SEG + PROPSEG + PSEG1 + 2 )/(SYCN_SEG + PROPSEG + PSEG1 + 2 + PSEG2 + 1)

SYNC_SEG = 1 (fixed)
PROPSEG = 3
PSEG1 = 2
PSEG2 = 1

Overview

This example demonstrates the transmission of Flexi-date rate transmission with bit rate switching enable to transfer the payload at 8 Mbps. The payload in each message buffer can be up to 64 MB in size

"Successfully Received data from all MBs multiple times at high speed " and "All Done" printed to the console signifies the received messages are received correctly.

"Test failed" printed to the console signifies that the test example has failed. Other errors are also printed if any of the driver operation fails in between and the code is terminated.

User Configuration Macros

  1. STANDARDFRAME : This macro define whether the message buffers are transmitted with standard ID or extended ID. This macro should be defined for standard frame and commented for extended frames. Macro should be defined/undefined on both core0 and core1.
  2. ISOCOMPLIANT_FD : This macro enables the ISO complaint FD transfers.
  3. DLC : This macro defines the size of CANFD payload. This can be defined depending on the number of bytes to be transferred in each payload Based on ADI_CANFD0_CFG_BLOCK0_MBSIZE/ADI_CANFD1_CFG_BLOCK0_MBSIZE macro defined in config file message buffers can be upto 64 bytes. So DLC should be configured in accordance with these macros in config files for both core0 and core1

Hardware Setup

  1. Connect the DB9 cable between J7 and J8 on EV-SOMCRR-EZKIT
  2. Run core 0 to enable Core1 and Core2 and configure CANFD0 for TX
  3. Run core 1 to configure CANFD1 for RX
  4. Core1 will compare the received data with the reference data and declare the test status

Pinmuxing

The following pins are used for the CANFD operation:

  1. CANFD0_RX
  2. CANFD0_TX
  3. CANFD1_RX
  4. CANFD1_TX

External connections

Connect the DB9 cable between J7 and J8 on EV-SOMCRR-EZKIT
