Description

This OSPI driver test example illustrates the use of Direct mode of access of OSPI to read and write the data to the flash memory. This example works standalone on EV-SC59x-SOM/EV-21593-SOM, as well as supported on both EV-SOMCRR-EZKIT and EV-SOMCRR-EZLITE.

The example does following:

  1. Initializes the SPU for making MDMA secure for memory accesses.
  2. Enables the access to ISSI Quad flash on board by configuring the soft config switch through TWI2.
  3. Erases the Block0 of flash using the STIG mode of OSPI controller.
  4. Performs the read operation in Single SPI mode using the Direct access mode of OSPI controller using MDMA0 to verify the Erased data.
  5. Programs 1024 bytes to flash in Single SPI mode using the Direct access mode of OSPI controller using MDMA0.
  6. Configures the ISSI IS25LP512M flash to enter the QPI mode.
  7. Configures the controller to do direct read transaction compatible to QPI mode.
  8. Performs the read operation in QPI mode (Command, Address and data all sent in Quad mode) using the Direct access mode of OSPI controller using MDMA0.
  9. Verifies the read back data.
  10. Takes the flash out of QPI mode.

Overview

The example uses the Direct access mode of the OSPI controller to do the direct read and write accesses to the flash device. This involves configuring the controller through API provided for direct read and write accesses. Individual commands to configure the flash or Erase the flash and done through the STIG mode

"Data transfer completed successfully" and "All Done" printed to the console signifies the receive buffer compares with the expected result buffer.

"Data transfer failed with errors" printed to the console signifies that the test example has failed. Other errors are also printed if any of the driver operation fails in between and the code is terminated.

User Configuration Macros

  1. Disable both EV_SOMCRR_EZKIT_SUPPORT & EV_SOMCRR_EZLITE_SUPPORT in ospi_flashdirectaccess.h file to verify the example in EV-SC59x-SOM/EV-21593-SOM alone without connecting any CRR boards.
  2. Enable EV_SOMCRR_EZKIT_SUPPORT in ospi_flashdirectaccess.h file to verify the example on EV-SOMCRR-EZKIT.
  3. Enable EV_SOMCRR_EZLITE_SUPPORT in ospi_flashdirectaccess.h file to verify the example on EV-SOMCRR-EZLITE.
  4. Note: By default both EV_SOMCRR_EZKIT_SUPPORT & EV_SOMCRR_EZLITE_SUPPORT are disabled in ospi_flashdirectaccess.h.

Pinmuxing

The following pins are used for the OSPI operation:

  1. OSPI_CLK
  2. OSPI_MISO
  3. OSPI_MOSI
  4. OSPI_D2
  5. OSPI_D3
  6. OSPI_SEL1
