Description

This OSPI driver test example illustrates the use of OSPI-Phy Auto Calibration in REF_Clock mode and read the data from the flash memory at 80Mhz.

The example does following:

  1. Initializes the SPU for making MDMA secure for memory accesses.
  2. Enables the access to ISSI Quad flash on board by configuring the soft config switch through TWI2.
  3. Erases the Block0 of flash using the STIG mode of OSPI controller.
  4. Using Non-Phy mode program 1024 bytes to flash in Single SPI mode using the Direct access mode of OSPI controller using MDMA0.
  5. Configures the ISSI IS25LP512M flash to enter the Quad IO mode.
  6. Configures the controller to do direct read transaction compatible to QSPI mode.
  7. Initialize OSPI-Phy to REF_Clock mode and do Auto Calibration to configure appropriate RXDLL and TXDLL values for further Phy mode transfers .
  8. Using Phy mode perform the read operation in Quad IO DTR mode (Command in Single mode, Address and data sent in Quad mode) using the Direct access mode of OSPI controller using MDMA0.
  9. Verifies the read back data.

Processor

ADSP-SC594

ADSP-SC598

Overview

The example uses the Direct access mode of the OSPI controller to do the direct write accesses to the flash device. And enable Phy mode (With Auto Calibration feature) and do direct read accesses from flash device. This involves configuring the controller through API provided for direct read, write accesses and Phy Init. Individual commands to configure the flash or Erase the flash and done through the STIG mode

"Data transfer completed successfully" and "All Done" printed to the console signifies the receive buffer compares with the expected result buffer.

"Data transfer failed with errors" printed to the console signifies that the test example has failed. Other errors are also printed if any of the driver operation fails in between and the code is terminated.

Hardware Setup

This example will work only with EV-SC594-SOM/EV-SC598-SOM alone, without connecting any EV-SOMCRR-EZKIT or EV-SOMCRR-EZLITE board. Since the OSPI lines are shared with another flash device in SOMCRR boards and running at High Speed (80Mhz). Connecting SOMCRR-EZKIT or EV-SOMCRR-EZLITE may cause signal integrity issues and example may fail.

Pinmuxing

The following pins are used for the OSPI operation:

  1. OSPI_CLK
  2. OSPI_MISO
  3. OSPI_MOSI
  4. OSPI_D2
  5. OSPI_D3
  6. OSPI_SEL1
