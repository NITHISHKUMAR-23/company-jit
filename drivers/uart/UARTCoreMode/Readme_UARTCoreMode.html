1. Description

This example demonstrates transfer of data in core mode between different UART's. UART transfers in case of Core mode happen in blocking mode which means that the API will block until the desired number of bytes are written/read.This example is supported both on EV-SOMCRR-EZKIT and EV-SOMCRR-EZLITE.

2. Processor

  • ADSP-21593
  • ADSP-SC594
  • ADSP-SC598

3. Overview

Example opens two UART instances by default @Note: Since this example uses core mode blocking mode of transfer we are transferring 8 bytes of data only, as that is the size of the receive FIFO, in case the data to be transferred is more than 8 bytes, data transfer should be done across two ADSP-21593/SC594/SC598 EZ-KIT's.

4. Hardware Setup

There are external connections which are required in case of this example wherein EV-SOMCRR-BRKOUT probing adapter board needs to be connected to EV-ADSP-21593 or EV-ADSP-SC594 or EV-ADSP-SC598 SOM EZ-KIT.

5. User configuration macros

    UARTDEVA = ADI_UART_0
    UARTDEVB = ADI_UART_1

6. External connections

List of UART pins which are available on EV-SOMCRR-BRKOUT probing adapter 

    UART 0 Tx - Pin 22(P3)
    UART 1 Rx - Pin 17(P4)


    As per the example UARTDEVA is UART Tx and UARTDEVB is UART Rx.

    By Default: UARTDEVA = UART 0
                UARTDEVB = UART 1

    @Note: care must be taken that the jumper wires are connected according to the UART configuration.

    As per the configuration, UART 0 configured as Tx should be connected to UART 1 configured as Rx and it is required that a jumper wire needs to be connected between Pin 22(P3) and Pin 17(P4) on EV-SOMCRR-BRKOUT probing adapter.

7. Pinmuxing

Following is the pinmux configuration:

  • UART0 (RX, TX)
  • UART1 (RX, TX)
  • GPIO (unavailable) with ADSP-21593: PA06, PA07, PA14, PA15
  • GPIO (unavailable) with ADSP-SC594: PD08, PD09, PD04, PD05
  • GPIO (unavailable) with ADSP-SC598: PD08, PD09, PD04, PD05
